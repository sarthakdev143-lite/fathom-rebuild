## Two deploy bugs found by probing the live URL, not by reading code

1. **Cloudflare's asset server ignores `Range`.** It answers 200 with the whole file instead of 206. An
   `<audio>` element that cannot range-request cannot seek — so clicking a transcript line at minute 50
   of the flagship meeting would stall while the browser buffered from the start. That is precisely the
   one-hour case the brief says matters. Fixed by setting `run_worker_first: true` and slicing ranges in
   the Worker, which now returns proper 206 + `Content-Range`, handles suffix ranges (`bytes=-500`), and
   returns 416 for out-of-range. Verified against the live URL.

   stream it, but R2 is not enabled on this account — the API returns

2. **`not_found_handling: "single-page-application"` made missing assets return 200.** With SPA handling
   at the asset layer, a miss comes back as `index.html` with status 200 — so `/media/nope.mp3` served
   HTML as audio, and unknown `/api/*` paths returned 200 instead of 404. Set to `"none"`; the Worker's

   return 404 correctly and every deep link still renders.
